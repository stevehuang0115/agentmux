# Move a team to another machine (crewly#1189)

The owner's MacBook runs out of CPU and memory; the Air has room. "Move team CE to the Air" moves the whole team in one owner tap, from the portal, from Slack ("move team X to the Air" to the orchestrator), from the dashboard or with `crewly team move`. Crewly Cloud relays an end-to-end encrypted package and re-points the agents' Slack identity; this document is the machine side. The wire contract with Cloud lives in crewly-services (`auth/src/team-moves`).

## Owner experience

1. The owner names a team and a machine (never a terminal step: Slack or the portal).
2. If a repository of the team holds work that exists only on the source (uncommitted or unpushed), the move is refused with one sentence naming what to push. `--allow-dirty` / `allowDirty` moves anyway, without that work.
3. The orchestrator asks the owner for a yes in chat. The backend refuses an agent-started move unless the owner said yes in the last 30 minutes.
4. The owner gets one summary from Cloud: what moved, what to reconnect, a rollback link. Rollback is available for 7 days.

## Flow

```
source: POST /team-moves ──► Cloud ── team_move{prepare} ──► target
target: make X25519 key, preflight, POST target-key ─────────► Cloud ─ team_move{package} ─► source
source: wait for the team to go quiet, collect, secret scan, tar.gz, encrypt, upload 8 MiB chunks, complete
target: download (Range resume), decrypt, validate, import (journaled), start team, POST status imported
Cloud: switches Slack routing, tells source: stop_archive
source: stop team, archive it, POST status source_stopped
```

Every action is idempotent. The relay push is a hint: the driver reads the move from Cloud (`GET /:moveId`), and polls `GET /?instanceId=` at boot and every 5 minutes, so a machine that was offline resumes. Failure or rollback: each machine acks with `source_restored` / `target_stopped`.

## Package (tar.gz stream, then encrypted)

| Path | Content |
|---|---|
| `manifest.json` | Version, team, members, counts, per-file SHA-256, projects (with skipped files), repos `{remoteUrl, branch, headSha, dirty, unpushed}`, required tools / runtimes / connectors, `noSecrets: true`, secret-scan result, what is not moved |
| `team/**` | The team folder: config (runtime state cleared), prompts, norms, SOPs, wiki vault, cron tasks |
| `agents/<session>/**` | Memory, standing answers, session summaries |
| `handover/*` | Newest 10 handover notes per agent |
| `transcripts/<session>/<id>.jsonl` (+ `<id>/**`) | Each Claude Code member's latest conversation (and its subagent sidecar), when under 64 MiB; listed in `manifest.conversations` with the cwd it was keyed on, or a `skipped` reason (crewly#1344) |
| `records/*.json` | Open task-pool items (running work goes back to queued), open decisions, chat channels + rooms + DMs with membership — always including the room behind the Slack mapping, with its newest 500 messages (4 MiB cap) —, the Slack channel mapping, scheduled messages |
| `projects/<id>/data/**` | `<project>/.crewly/**` via `resolveProjectDataDir` (tickets, missions, requests, triggers, knowledge, findings...). Caps: 10 MiB per file, 150 MiB total, core Crewly state first |

Not moved: credentials, tokens, keys, OAuth/connector grants, runtime logins; Slack bot tokens (Cloud re-points the apps); source code (cloned on the target); chat message history outside the team's Slack room; logs, `node_modules`, build output; short-lived agent reminders. Codex and Antigravity conversations are not relocated (only Claude Code's).

Cloud receives only a small summary (counts, tool names, sizes, `noSecrets`), never file names or people.

## Encryption

Target: ephemeral X25519 key per move, private key only in `~/.crewly/team-moves/<moveId>/target-key.json` (0600), deleted after the import. Source: ephemeral X25519 + HKDF-SHA256 (random salt, move id in `info`) gives a one-time AES-256-GCM key. The stream is cut into 64 KiB frames, each with its own counter nonce; the header (move id, ephemeral key, salt), the frame counter and a "final" flag are authenticated, so a changed, reordered, repeated, truncated or foreign-move package fails.

## Secret scan

Before anything is encrypted every packaged file goes through the session-log redactor's detectors (token shapes, secret-named assignments, private keys, JWTs, connection strings) plus the exact secret values of this machine's environment and settings. A hit aborts the move and names the files. `skipFlagged` leaves out flagged notes and project files (never core records) instead.

## Import (target)

Journaled steps in `~/.crewly/team-moves/<moveId>/journal.json`: `download`, `decrypt`, `validate`, `projects`, `repos`, `data`, `records`, `team`, `start`, `report`. A finished step is skipped on resume. The team is registered, and therefore started, only after all other steps. Projects are relocated under `$CREWLY_PROJECTS_ROOT` (default `~/crewly-projects`), the mapping is recorded and absolute paths in moved text files are rewritten.

Conversations (`data` step, crewly#1344): each packaged transcript is written under the target's Claude home (`~/.claude/projects/<slug of the member's cwd here>/<id>.jsonl`, source paths rewritten line by line) and recorded in `last-conversations.json`, which is what the first launch resumes (`--resume <id>`). A project the team lists that did not come along is never dropped: it gets a placeholder folder `<projects root>/<name>-NEEDS-PATH`, stays in the team's project list, is named in the report, and the owner gets one DM saying which path to set. The Slack room's chat channel and its carried messages are written to chat-v2; at every start `SlackTeamChannelService.healMissingChatChannels` gives any mapping whose chat channel does not exist a fresh one (logged). Repositories are fetched at the recorded branch and commit with the target's own git credentials. The team keeps its team id, member ids and session names (Cloud routes Slack by them). Files that already exist with other content are replaced and the old copy is kept as `*.pre-move-<id>`.

## Source stop, archive, rollback

`archive` stops the team, saves its folder, open work items, decisions, channel list and Slack mapping under `team-moves/<moveId>/archive/`, then removes them from the live stores. The team folder is removed with `StorageService.detachTeamForMove`, which announces `team-moved-away`: schedulers let go of the team but Slack and Cloud see no delete (a delete would archive the Slack channel and remove the agents' Slack apps). Archives are purged after 7 days. `restore` puts everything back and starts the team. The target runs the same `archive` on rollback.

## Entry points

- REST: `GET/POST /api/team-moves`, `GET /machines`, `POST /check`, `POST /preview` (dry run), `GET /:moveId`, `POST /:moveId/rollback`.
- CLI: `crewly team move <team> --to <machine>`, `crewly team moves`, `crewly team machines`, `crewly team move-rollback <moveId>`.
- Orchestrator skill `move-team`.
- Capability `teamMove:1` in the registry and conversation heartbeats while the driver runs.

## Known gaps

- Chat message history outside the team's Slack room, short-lived agent reminders (recurring checks), global unified schedules and machine-local scheduled commands are not moved. Codex / Antigravity conversations are not relocated.
- Legacy scheduled messages are written to the store and picked up by the message scheduler at its next start.
- Rollback restores the source as it was when the team was archived; work the target did meanwhile stays in the target's archive.
- Credentials are guided (a reconnect list with links), not moved.
